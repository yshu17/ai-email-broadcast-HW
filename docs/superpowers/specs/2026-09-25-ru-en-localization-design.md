# Локализация RU/EN — дизайн

Статус: согласован пользователем 2026-09-25 (вариант «без языка письма в кампании»).

## Цель

Весь интерфейс на русском, с переключателем RU | EN. Русский — язык по умолчанию. Без новых зависимостей и без изменения URL.

## Объём

Переводится:

- весь интерфейс админки (30 файлов `.tsx`): страницы, формы, диалоги, подсказки, кнопки, панель редактора, `aria-label`, `title`, `placeholder`, заголовок вкладки и `<html lang>`;
- страница входа;
- публичная страница отписки получателя;
- тексты ошибок API (сейчас ~68 английских строк, показываются в интерфейсе);
- даты и числа (язык интерфейса; часовой пояс остаётся браузерным);
- служебный текст писем: подвал «Вы получили это письмо…/Отписаться», строка `Отписаться:` в текстовой версии, заготовки тестовых писем.

Имена статусов (`DRAFT`, `SCHEDULED`, `SENT` …) показываются в интерфейсе через словарь `status.*`; значения в БД и в API остаются прежними.

Не переводится: данные пользователя (имена, темы и тела писем, названия списков), тексты ответов SMTP-серверов, логи, JSON воркера.

Вне объёма (решено пользователем): язык письма отдельно для каждой кампании и поле `campaigns.language`. Миграций нет.

## Архитектура

### Ядро — `src/i18n/`

- `en.ts` — эталонный словарь (плоские ключи вида `campaigns.title`). `type TKey = keyof typeof en`.
- `ru.ts` — `Record<TKey, string>`: пропущенный или лишний ключ = ошибка `tsc`.
- Плюральные ключи: `key.one|few|many|other`; выбор формы через `Intl.PluralRules(locale)`.
- `translate(locale, key, params?)` — чистая функция (интерполяция `{name}`, плюрали через `params.count`). Работает на сервере и в браузере.
- `locale.ts` — `Locale = "ru" | "en"`, `DEFAULT_LOCALE = "ru"`, `LOCALE_COOKIE = "locale"`, `normalizeLocale()`, `intlTag(locale)` (`ru-RU` / `en-US`).

### Определение языка

| Где | Порядок |
| --- | --- |
| Страницы и layout (сервер) | cookie `locale` → `ru` |
| API | заголовок `x-locale` → cookie → `en` (для тестов, curl, cron) |
| Публичная страница отписки | cookie → `Accept-Language` (`ru*` → `ru`, иначе `en`) → `EMAIL_LANGUAGE` |
| Письма | `EMAIL_LANGUAGE` (`ru` по умолчанию) — не зависит от языка интерфейса администратора |

`getLocale()` (сервер) читает `next/headers` и при отсутствии контекста запроса возвращает язык по умолчанию: вызов вне запроса (тесты) не падает.

### Клиент

- `LocaleProvider` (client) получает `locale` из корневого `layout.tsx` (server) и раздаёт через контекст.
- `useT()` возвращает `{ t, tp, locale, formatDate, formatNumber }`. Без провайдера (SSR-тесты) значение по умолчанию — `en`, чтобы существующие тесты разметки остались как есть.
- `api()` в `ui.tsx` добавляет `x-locale`. `ApiError` несёт уже переведённый текст.
- `LanguageSwitcher`: кнопки `RU` / `EN` (`aria-pressed`), пишет cookie (`path=/; max-age=1 год; SameSite=Lax`) и вызывает `router.refresh()`. Стоит в шапке `Nav`, на странице входа и на странице отписки.

### Сервер

- `HttpError` получает необязательные `key` и `params`. Хелперы `badRequest`, `conflict`, `notFound` принимают ключ словаря. `handle()` переводит по языку запроса. Поле `error` остаётся строкой, `code` и `field` без изменений.
- Ключи ошибок лежат в общем словаре под префиксом `error.*`.
- Строки в успешных ответах, которые показываются пользователю (`Test email sent to …`, оценка длительности), либо переводятся по языку запроса, либо заменяются на числовые поля с форматированием на клиенте.
- Письма: `buildMessage` получает `language` (по умолчанию `EMAIL_LANGUAGE`).

## Проверки

1. `tests/i18n-dictionaries.test.ts`: одинаковые ключи в `ru` и `en`, непустые значения, одинаковый набор `{параметров}`, у плюральных ключей есть формы `one/few/many/other` для `ru` и `one/other` для `en`.
2. `tests/i18n-hardcoded.test.ts`: разбор `src/app/**/*.tsx` и `src/components/**/*.tsx` через TypeScript AST; JSX-текст и атрибуты `title`, `placeholder`, `aria-label`, `alt`, а также строки в `alert`/`confirm` не содержат латинских слов вне списка исключений (имена бренда, `HTML`, `SMTP`, коды и т.п.).
3. Рендер ключевых экранов на обоих языках: список кампаний, диалог отмены, последний шаг мастера, отписка, письмо.
4. API: одна и та же ошибка на `ru` (заголовок) и `en` (по умолчанию).
5. Плюрали `ru`: 1, 2, 5, 11, 21, 22, 25.
6. Существующие 603 теста проходят без правок.

## Риски

- Большой диф; смягчается тем, что словарь — единственное место текстов, а сканер ловит забытое.
- Хардкод в серверных ответах воркера/логов остаётся английским намеренно.
- Изменение языка писем по умолчанию на `ru` меняет подвал для новых отправок; возврат — `EMAIL_LANGUAGE=en`.
